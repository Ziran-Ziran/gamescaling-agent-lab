# 固定视觉读出的频谱特征缓存

本实验只优化[冻结视觉读出](vision-readout.md)的频谱图编码。相同模型、任务头、标准化、CPU 线程数与硬件下，比较每次重新编码和 CPU LRU 缓存；不更新权重，不运行原语言/动作解码器。RGB 始终重新编码。频谱图片来自人工合成 WAV，不能把命中率或收益推广为真实游戏音频的表现。

## 合同与审计

`spectral_cache.py` 使用完整编码器身份与精确 RGB 像素摘要构造键，不使用频率标签、教师动作、奖励或 reset 信息。容量64，4096维 float32 向量的有效载荷上限1MiB，另有元数据开销。PNG 编码差异不会改变相同像素的键；像素差异不能近似合并。命中返回副本，原编码记录与本次查询/复制成本分开保存，拒绝改变编码器身份或混用编码器实例。

每次请求仍读取并校验 WAV、时钟、窗口与可用时间，生成 STFT 后才查缓存。缺失、未来或过期输入直接使用固定训练缺失特征并保留缺失掩码，不查缓存；合法静音仍是有效输入。缓存不能把过去的有效输入复活成当前有效输入。每张图的视觉调用形状保持不变。

`vision_cache_compare` 在 CPU 上重新检查输入和每个新特征文件，加载固定头逐位重算 logits，独立重建键、LRU、原特征来源和命中/未命中/淘汰计数；不信任运行程序声明的命中标记。实际回合还重放 RGB、动作和奖励，核对原始单调时钟与汇总。原读出比较器默认仍要求完整视觉调用；缓存调用数只由新审计器重建后显式传入。

## 固定协议

基座为 `THUSI-Lab/GameScaling-0.8B-S3` revision `1b89640dcf2ef51fb53ad9338a0725e9622dd200`，权重 SHA256 `d553c0796833691e32277a937db649eaac39bae9a0028a63c964c12a261c2dfa`。视觉特征和任务头保持原实验身份；联合200步读出的 `readout.pt` SHA256 为 `4734d42b735bbe30c9b0631e73f0fb7f3aa037fa6102989ea129f5680b34e208`。RTX 5070 Ti Laptop、bf16 视觉编码器、CPU float32 头、四个 CPU 线程，Torch 2.10.0+cu128 / Transformers 5.14.1。原快内核依赖缺失，使用 Torch 回退，不在对照中更换内核。

训练 reset 的冷/热冒烟先完成并排除在正式结果外。正式来源为原联合头 IID `aligned` 的32个保存观测：reach 26000–26007，每个上下文两种颜色布局×两种音调。离线重复三次，共96对/192请求；顺序交替，无失败后再运行同样32个 reset 的实际配对回合，共64回合。两阶段分别清空缓存，各有两个来源观测×两组的4次显式 warmup，完整保存但不计入正式分位数。每阶段独立受共享重任务锁保护，正式计时期间不并行测试。

离线主指标 `processing` 从原始 RGB 哈希/读取开始，包含 WAV 哈希/读取/因果检查、STFT、两种视觉路径、头计算、选类和安全过滤。新数值特征的证据写入单列，位于离线主指标之外。离线没有实际采样、传输、排队或执行成本。

实际回合使用新发生的200ms传感器窗口和200ms动作窗口；世界在决策期间暂停。两组都在动作开始前同步保存相同内容的特征证据。主要比较观测到实际动作开始，另报告到动作结束及传感器窗口开始到动作结束。未单独测出的 PNG/WAV 落盘、传输和排队子项保留空值，不杜撰分解；落盘与记录成本仍包含在实际总延迟内。各分项分位数不能直接相加。

## 复现入口

先按 [vision-readout](vision-readout.md) 生成并审计源回合及联合头；使用实际本机 Python、模型、锁和输出路径设置变量，不从文档猜测路径。运行不下载模型。

```bash
# READOUT: joint-mlp200目录；SOURCE: 已完成的联合头IID八条件评测目录
# EXPECTED_HEAD: 运行前冻结的readout.pt摘要，不从待测结果反推
$PY scripts/resource_guard.py --lock "$GPU_LOCK" --seconds 900 -- \
  $PY -m scripts.training.vision_cache_benchmark --model "$MODEL" \
  --readout "$READOUT" --expected-readout-sha256 "$EXPECTED_HEAD" \
  --source "$SOURCE" --phase offline --output output/cache-offline
$PY -m scripts.training.vision_cache_compare --run output/cache-offline \
  --readout "$READOUT" --source "$SOURCE" --output output/cache-offline-audit.json
# 上一个进程正常结束且审计通过后，才开始实际回合；不能共用输出目录。
$PY scripts/resource_guard.py --lock "$GPU_LOCK" --seconds 900 -- \
  $PY -m scripts.training.vision_cache_benchmark --model "$MODEL" \
  --readout "$READOUT" --expected-readout-sha256 "$EXPECTED_HEAD" \
  --source "$SOURCE" --phase live --output output/cache-live
$PY -m scripts.training.vision_cache_compare --run output/cache-live \
  --readout "$READOUT" --source "$SOURCE" --output output/cache-live-audit.json
```

首次冒烟使用独立 TRAIN pilot 来源和 `--phase pilot`，其3次请求为无缓存/冷缓存/热缓存，不能替代正式测量。每轮输出配置、全部请求、缓存原始记录、数值特征、运行状态与汇总；实际阶段另有原始传感器/动作/奖励账本。原始文件、模型、特征和权重都留在忽略目录，只发布代码、协议与完整汇总。

## 已完成的离线结果

2026-10-27，96对全部完成、错误0。所有成对特征、原始 logits 和过滤后动作逐位一致；CPU 审计重算头最大差为0。

| 离线指标 | 无缓存 | 缓存 |
|---|---:|---:|
| 正式请求 / 错误 | 96 / 0 | 96 / 0 |
| processing P50 | 131.47ms | 94.70ms |
| processing 经验 P95 | 210.98ms | 158.86ms |
| processing 超过200ms | 6/96 | 0/96 |
| 音频视觉/缓存调用 P50 | 34.43ms | 0.54ms |
| WAV读取和因果校验 P50 | 46.53ms | 43.25ms |
| 主处理外证据保存 P50 | 30.67ms | 19.43ms |

配对主处理时间比的中位数为1.405；分位数使用经验 nearest-rank P95。正式缓存96次查询中95次命中、1次未命中；另有预热2次未命中，总共3个不同频谱像素条目，0次淘汰，峰值 CUDA 分配1676.20MiB。两种音调不等于只有两种精确像素，第三种真实未命中没有剔除。

这是8个上下文的32个初始观测各重复三次，96对不是96个独立上下文；收益同时包含实际文件系统抖动，未宣称统计显著性或内核归因。离线证据保存位于主要计时之外，不能将94.70ms说成观测到执行完成或持续实时游戏延迟。

## 实际回合结果

同样32个 reset 分别由两组真实执行，共64回合、64次动作、错误0；两组各32/32成功，平均回报均0.99。全部配对的 RGB/频谱特征、原始 logits 和实际动作一致。CPU 审计逐位重算头输出、复核窗口和实际动作时钟、奖励链与全部汇总，最大 logits 差0。

| 实际回合指标 | 无缓存 | 缓存 |
|---|---:|---:|
| 观测到动作开始 P50 | 210.69ms | 195.02ms |
| 观测到动作开始经验 P95 | 243.26ms | 258.71ms |
| 观测到动作开始超过200ms | 19/32 | 12/32 |
| processing P50 / P95 | 117.38 / 145.02ms | 88.63 / 131.69ms |
| 观测到动作结束 P50 / P95 | 411.15 / 443.45ms | 395.26 / 458.91ms |
| 传感器窗口开始到动作结束 P50 / P95 | 612.28 / 644.83ms | 596.89 / 660.12ms |
| 观测到 policy 开始 P50 | 50.36ms | 61.15ms |
| 特征证据保存 P50 | 23.08ms | 20.15ms |
| 实际动作窗口 P50 | 200.22ms | 200.25ms |

主要实际指标的配对中位速度比1.080。正式缓存32次查询中31命中、1未命中，另有预热2次未命中，最终3条目、0淘汰；峰值 CUDA 分配1676.20MiB。缓存查询子项 P50 从34.64ms降为0.51ms，但观测后至 policy 开始的记录等开销和其他抖动仍然存在。该测量没有逐项归因这些波动。

**P50 下降不代表尾延迟改善**：实际 P95 在本次固定负载下变差，缓存组仍有12/32超过200ms，到动作完成仍约395ms。保留这项负结果；既不能用离线1.405速度比替代实际1.080，也不能把缓存头路径称为原模型实时游戏控制。真实音频通常不会产生如此高比例的完全相同频谱像素，本次没有测量其命中率。

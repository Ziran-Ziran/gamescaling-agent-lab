# 架构与能力边界

目标链路：有授权的多游戏轨迹 → 数据合同与按游戏划分 → 模态编码/融合 → SFT/LoRA 与反馈训练 → 能力/延迟/成本评测 → 推理策略 → 键鼠执行及真实反馈。

已有：controller 的截图、官方策略桥接、回环端点校验、动作过滤、限时与监督停止、实际动作历史、保存图评估。它是早期 Windows 实验，不是训练框架或通用玩家完成品。

新增离线模块位于 `scripts/training/`：episode 审计/转换、因果历史与动作损失边界、本地 RGB 模型后端、PEFT LoRA、包含优化器/RNG 的检查点、冻结保存图评测和显式合成数据生成。`scripts/resource_guard.py` 管理跨对话重任务锁与进程树时限；训练代码不导入桌面控制。入口与证据解释见 [training.md](training.md)。

待实现/验收：真实多游戏训练与任务评测、奖励及反馈管线、音频/深度/结构化状态编码器、模态缺失处理和低延迟调度。experiments 仍是设计配置，validate_project 只是静态合同检查，独立 CLI 不冒充这些配置的执行器。

推理输入与动作反馈需绑定 episode/frame/timestamp；不能把模型建议当实际动作历史。训练期引擎特权信息和部署期允许的信息分开；额外输入适配需训练验证，不能给现有 RGB API 加字段后就宣称多模态能力。

本仓库不依赖 SITP、SLAM、地图或 UE5。引擎后端未来只是可选输入适配器；每个适配器有独立信息权限、单位和时钟声明。

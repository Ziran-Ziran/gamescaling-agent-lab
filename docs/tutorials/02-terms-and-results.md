# 02：术语和实验成绩怎么读

教学补写：2026-10-27。案例来自已经保存并审计的夜间实验，不是新一轮训练。配合[第01篇](01-training-night.md)阅读。

## 先把常见词换成普通话

| 词 | 在本项目中是什么意思 | 容易误会的地方 |
|---|---|---|
| 模型参数、权重 | 从训练中学到的一大批数字 | 0.8B约8亿参数，不是0.8GB文件 |
| 推理 | 使用当前学到的东西作一次判断 | 产生了答案，不等于正在继续学习 |
| SFT | 用正确示范教模型模仿 | 损失小，不等于实际任务一定完成 |
| LoRA、adapter | 训练较小的附加参数，搭配原模型使用 | 附加文件不是完整模型，也不是外挂的正确答案表 |
| step、更新 | 优化器完成一次参数调整 | 不等于一张新图片、一次按键或一局游戏 |
| episode、回合 | 从规定起点到成功、失败或到达上限的一次任务 | 一局可能执行多个动作 |
| checkpoint、检查点 | 包含参数和继续训练状态的存档 | 只存模型文件不一定能原样恢复 |
| seed、随机种子 | 约定随机过程从什么状态开始 | 只有相同种子还不能保证不同硬件结果相同 |
| batch、组批 | 一次更新前使用的一组样本 | 同样200更新，组批不同意味着数据和计算可能不同 |
| 泛化 | 在没学过的任务或条件下也能完成目标 | 同一种小型游戏换几个种子不等于会玩陌生大型游戏 |
| 真值 | 用来核对结果的已知真实状态或正确目标 | 考试时把它给模型看，就是泄漏答案 |
| CI | 提交后自动运行的检查 | 检查通过不是模型能力考试通过 |
| PR | 提交一组改动供检查、审阅和合并 | 18个PR不是18轮训练，也不是18项能力提升 |

“24个可训练张量”里的**张量**可以先理解成一块数字数组；不是只训练了24个数字。精确文件和数量放在技术文档里，不必现在背下来。

## 训练完成与成绩改善要分开看

| 层次 | 我们实际看什么 | 本轮能举出的例子 |
|---|---|---|
| 管线能运行 | 数据读入、计算学习信号、更新、保存是否真的执行 | 颜色规则冒烟实验 |
| 真实模型训练完成 | 已有GameScaling权重上的可训练部分确实改变，检查点与恢复有证据 | 多轮实际LoRA训练与恢复对照 |
| 某套任务成绩改善 | 固定考试下，动作、回报或成功率相对基线变化 | 某批四局hazard从0/4到4/4 |
| 广泛泛化或部署可用 | 多种独立游戏、任务、种子及连续环境上的可靠表现 | 本轮未验收 |

“真实模型训练”中的“真实”指真的运行了模型和参数更新，不是说用了真实商业游戏数据。训练可以实际发生在合成题上；题目简单的限制仍然存在。

## 为什么成功率提高了，仍可能退步

看最新一批hazard题，先用一个完全对应本轮数字的示意：

| 固定八题 | 原模型 | RGB重放后 |
|---|---|---|
| 原来答对的两题 | 对、对 | 错、错 |
| 原来答错的六题 | 全错 | 全对 |
| 总成功 | 2/8 | 6/8 |
| 原来会做的题保留了多少 | 作为基准 | 0/2 |

总分提高和旧本领保留不是同一回事。这批实际记录中，重放模型丢失的两例是踩hazard死亡，所以我们同时写“总成功6/8”和“原成功保留0/2”。

**保留率的分母是原模型成功的题数**。如果原模型本来0/4成功，就没有原成功可以检查，保留比例写 `null`，意思是这里没有可计算的信息，不能写成“100%保持”。

另一类任务reach中，原模型4/8成功，重放后8/8，并保留了原来的4题，这才支持本套题的原成功保留4/4。不能把reach的这个结论搬给hazard。

## 对照实验为什么要固定条件

比较模型前后时，尽量保持题目、规则、输入、生成设置和机器相同。否则“更好”可能只是因为新题更容易，或换了一块更快的显卡。

冻结评测的意思是先把考试方案定下来，再看结果。看到错题后可以分析原因，但若据此改模型，需要承认这些题已经影响了选择，并为下一轮准备独立验证与最终评测，不能继续把原考试当作没看过。

我们的声音组批实验同时改变了训练次数、有效组批、数据曝光等条件。因此可报告新方案的实际表现，不能只凭前后差异断言“全是组批方法的功劳”。

## 怎样判断模型是否利用了声音

人工声音任务中，同一画面可能因为音调不同而需要相反动作。

如果画面和声音都正确时16/16成功，把两种音调交换后0/16，去掉一个信息来源后8/16，就有证据表明该人工任务中的选择依赖二者的联合关系。只给接口新增一个“audio”字段，没有这样的行为对照，不能证明模型会利用声音。

缺失也要单独标记：没拿到声音与拿到了有效静音不是同一件事。声音必须属于当前画面之前可用的时间窗口，不能提前读到未来的信息。

这批成功仍不证明模型理解真实脚步、敌人位置或语音；它学到的是特定人工音调与画面的关系。

## 0.16秒为什么不等于完整动作只用0.16秒

**延迟**是从约定的起点到终点经过多久；先问“从哪里算到哪里”。

| 实际记录的数字 | 包含什么 | 没有说明什么 |
|---|---|---|
| 保存图处理P50约163ms | 读保存图、编码、首键判断、解析等 | 没有包含真实截图、排队与动作执行 |
| 实际回合采样到动作开始P50约278ms | 当前画面采样之后，到真正开始动作 | 还没执行完约200ms动作窗口 |
| 实际回合采样到动作结束P50约478ms | 采样之后到该动作执行结束 | 不含采样前渲染；世界仍在思考时暂停 |

这几行来自不同计时流程，不能把分项中位数任意相加，拼成一个新的实测结果。

**P50**就是中位数：一半记录比它快，一半比它慢。**P95**看靠慢的一端；本轮用排序后最近秩的经验值。例如36条记录取第35条作为P95，它并不保证未来95%的请求都比它快。

频谱缓存实验中，实际动作开始P50约211→195ms，但P95约243→259ms，变慢了。不能只选中间变快的数字宣布延迟整体改善。

## 大分数为什么也可能选错

模型对五个方向候选给出相对分数，不是直接给出“这局成功的概率”。这点在输出字段里已标为未校准。

最新重放组的16个单步RGB记录，候选分数全部≥0.99，仍有两次危险死亡。两次错误的S动作分数约0.999976和0.999934。

所以“候选中很偏向这个答案”和“这个答案实际上正确”不同。这里是已知失败的事后诊断，没有训练概率校准器，也没有执行“分数低就重试”的新策略。

## 为什么记录失败也很重要

最初的GPU恢复曾不逐位一致；第一轮音频适配没有融合收益；复习旧题仍损伤部分hazard；缓存的尾延迟变差。这些都是实验的一部分。

如果只留下成功，会让下一轮重复踩坑，也会误判问题已经解决。技术报告保留精确来源和数字；教学记录负责把这些失败变成能理解的经验。

## 三个自测问题

1. 两个模型都更新200次，一定花了相同数据和计算吗？
2. 一个模型以前0局成功，训练后4局成功，能否说旧能力保持100%？
3. 图像处理快了，为什么角色仍可能来不及行动？

参考答案：不一定，组批与每次使用的样本可能不同；不能，原成功为零时保留率无信息；还有采样、排队、传输、执行等环节，而且世界可能在思考时继续变化。
